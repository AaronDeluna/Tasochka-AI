# Как обучить Тасочку и поговорить с ней — простыми словами

Этот файл — пошаговая инструкция: **подготовить данные → обучить модель → пообщаться**.
Все команды запускай **из корня проекта** (`/Users/ivanmilovanov/Desktop/Tasochka AI`),
копируй одной строкой целиком.

Модель учится **с нуля**: сначала на большом объёме русского текста она учится
самому языку, потом на диалогах — отвечать как ассистент по имени «Тасочка».

Два сценария (ты выбрал оба):
- **Mac M4 16GB** — прототип: маленькая модель (~180M), чтобы проверить, что всё
  работает и модель начинает говорить по-русски.
- **Арендованный сервер (GPU 24GB+)** — финальный прогон: модель на **~1B** параметров.

## Шаг 1. Данные

Все датасеты лежат в `datasets/`, каждый источник — в своей подпапке. Трейнер
читает `datasets/` **рекурсивно**: просто положи новую папку с `.txt` — она
автоматически попадёт в обучение.

Скачать/обновить датасеты (скрипт сам раскладывает по подпапкам):

```bash
cd "/Users/ivanmilovanov/Desktop/Tasochka AI" && ./.venv/bin/python scripts/download_datasets.py
```

Главный источник **объёма** — большой веб-корпус **FineWeb-2 (rus_Cyrl)**. Он
стримится, поэтому качается ровно столько, сколько укажешь лимитом `--web-max-chars`
(в символах). Это важно из-за места на диске.

**Сколько текста нужно** (правило Chinchilla ≈ 20 токенов на параметр):

| Модель | Нужно текста | Флаг |
|---|---|---|
| ~180M (Mac) | ~4–8 GB | `--web-max-chars 3000000000` (3 GB, чтобы влезло на Mac) |
| ~1B (сервер) | ~60–90 GB | `--web-max-chars 80000000000` (80 GB, на сервере с местом) |

> ⚠️ **На Mac сейчас свободно ~14 GB.** Не качай большой корпус на Mac — только
> маленький срез для теста. Большой корпус качай уже **на сервере**, где есть диск.

Примеры:

```bash

cd "/Users/ivanmilovanov/Desktop/Tasochka AI" && ./.venv/bin/python scripts/download_datasets.py --web-max-chars 3000000000

# Сервер: полный веб-корпус под 1B (займёт часы и десятки GB)
python scripts/download_datasets.py --web-max-chars 80000000000
```

Полезные флаги: `--skip-web` (не качать веб-корпус), `--skip-wiki`, `--skip-saiga`
и т.д. — пропустить источник; `--max-items 1000` — качнуть по чуть-чуть для проверки.

Персона Тасочки (имя, «я — ИИ») генерируется отдельно, эти файлы уже лежат в

## Шаг 2. Обучение

### Вариант A — Mac, прототип ~180M (проверить, что всё работает)

```bash
cd "/Users/ivanmilovanov/Desktop/Tasochka AI" && ./.venv/bin/python -m tasochka.train --bf16 --tie-embeddings --vocab-size 16000 --embedding-dim 896 --num-layers 20 --num-heads 14 --num-kv-heads 2 --feed-forward-dim 2400 --context-length 512 --batch-size 8 --grad-accum 2 --max-steps 30000 --lr 3e-4 --warmup-steps 1000 --min-lr-ratio 0.1 --max-dataset-chars 13000000000 --val-every 500 --checkpoint-every 1000
```

### Вариант B — сервер, ~1B (финальный прогон)

Нужен GPU **24 GB+** (например A5000). PyTorch-бэкенд, bf16 обязательны.

```bash
python -m tasochka.train --backend torch --bf16 --compile --grad-checkpoint --tie-embeddings --vocab-size 32000 --embedding-dim 2048 --num-layers 24 --num-heads 16 --num-kv-heads 8 --feed-forward-dim 5504 --context-length 1024 --batch-size 8 --grad-accum 16 --max-steps 120000 --lr 2e-4 --warmup-steps 2000 --min-lr-ratio 0.05 --max-dataset-chars 90000000000 --val-every 500 --checkpoint-every 1000
```

> `--grad-checkpoint` пересчитывает активации в backward: ~30% медленнее, но
> резко меньше памяти — именно это позволяет 1B влезть в 24 GB.
> Эффективный батч здесь = `8 × 16 = 128` последовательностей = 131k токенов.

> Если не хватает видеопамяти (*out of memory*): уменьшай `--batch-size`
> (до 4 или 2) и во столько же раз увеличивай `--grad-accum` — эффективный
> батч останется тем же, а памяти нужно меньше.

Прервать обучение можно в любой момент (**Ctrl+C**). Повторный запуск **той же
команды** продолжит ровно с последнего чекпоинта — шаг, оптимизатор и learning
rate восстановятся сами.

## Что означают параметры (простым языком)

### 🧱 Размер и форма модели (влияют на «умность» и на то, влезет ли в память)

| Флаг | Простыми словами |
|---|---|
| `--embedding-dim` | «Ширина» модели — сколько чисел на каждое слово. Больше = умнее и тяжелее. 896 ≈ 180M, 2048 ≈ 1B. |
| `--num-layers` | Сколько слоёв-блоков друг над другом. Больше слоёв = глубже «мышление», но медленнее. |
| `--num-heads` | На сколько «голов внимания» делится каждый слой. Обычно `embedding-dim / 64` или `/128`. |
| `--num-kv-heads` | Приём GQA: меньше «голов памяти» → экономит память почти без потери качества. **Обязательно должно нацело делить `--num-heads`** (иначе запуск сразу упадёт с ошибкой): при 14 головах бери 2 или 7, при 16 — 4 или 8. `0` = столько же, сколько `--num-heads`. |
| `--feed-forward-dim` | Размер «думающего» слоя внутри блока. Обычно ~2.7× от `embedding-dim`. |
| `--tie-embeddings` | Переиспользовать таблицу слов на входе и выходе. Экономит параметры — **всегда включай**. |
| `--vocab-size` | Сколько токенов в словаре. Больше словарь = меньше токенов на тот же текст = быстрее обучение. Для русского замерено: 8k → 3.69 симв/токен, 32k → 4.56 (на 19% меньше токенов). Бери **16000** для модели ~180M и **32000** для 1B. |

> ⚠️ `--embedding-dim`, `--num-layers`, `--num-kv-heads`, `--tie-embeddings`
> задают **архитектуру**. Их нельзя поменять на середине обучения — только для
> новой модели. Хочешь другую архитектуру — удали старый чекпоинт:
> `rm -rf checkpoints/tasochka`.

### 💾 Что влезет в память (крутить при нехватке RAM/VRAM)

| Флаг | Простыми словами |
|---|---|
| `--context-length` | Сколько токенов модель видит за раз (длина «окна»). Больше = помнит длиннее, но заметно тяжелее. 512 на Mac, 1024 на сервере. |
| `--batch-size` | Сколько примеров считаем одновременно. Больше = быстрее и стабильнее, но жрёт память. Мало памяти → уменьшай. |
| `--grad-accum` | «Накопить градиент» за N шагов перед обновлением. Позволяет получить эффект большого батча при маленьком `--batch-size`. Эффективный батч = `batch-size × grad-accum`. |
| `--grad-checkpoint` | (только PyTorch) Не хранить активации, а пересчитывать их в backward. ~30% медленнее, зато сильно меньше памяти. Нужен для 1B на 24 GB. |

### 🎓 Как модель учится (скорость и стабильность обучения)

| Флаг | Простыми словами |
|---|---|
| `--max-steps` | Сколько всего шагов обучения. Больше = дольше учится и (до предела) умнее. |
| `--lr` | Learning rate — «размер шага» обучения. Слишком большой → loss скачет/взрывается; слишком маленький → учится вечность. 2e-4…3e-4 — норма. |
| `--warmup-steps` | Сколько первых шагов LR плавно разгоняется с нуля. Защищает от взрыва в начале. 1000–2000. |
| `--min-lr-ratio` | До какой доли от `--lr` опускать в конце (плавное затухание, cosine). 0.1 = до 10%. |
| `--weight-decay` | Лёгкое «притягивание весов к нулю» — защита от переобучения. 0.1 — стандарт. |
| `--grad-clip` | Обрезает слишком большие градиенты, чтобы обучение не «взрывалось». 1.0 — стандарт. |
| `--seed` | Зерно случайности. Одинаковый seed = воспроизводимый прогон. |

### ⚡ Скорость / железо

| Флаг | Простыми словами |
|---|---|
| `--bf16` | Mixed precision: считать в 16-битных числах (~1.4× быстрее), но веса и моменты оптимизатора хранить в 32-битных, иначе мелкие обновления теряются и обучение встаёт. Всегда включай. |
| `--compile` | (только сервер/PyTorch) Скомпилировать шаг в один граф — ещё +15–30% скорости. |
| `--backend` | `mlx` (Mac) или `torch` (сервер). Обычно определяется сам; на сервере укажи `--backend torch`. |
| `--device` | (PyTorch) `cuda` / `cpu` / `mps`. Обычно не нужен — выберется сам. |

### 📊 Данные, проверки и сохранения

| Флаг | Простыми словами |
|---|---|
| `--max-dataset-chars` | Сколько символов текста взять из корпуса. **По умолчанию всего 30 млн — это очень мало!** Для настоящего обучения ставь миллиарды (напр. `5000000000`). |
| `--val-fraction` | Какую долю данных отложить на проверку (0.02 = 2%). |
| `--val-every` | Каждые сколько шагов считать «оценку» (validation loss). |
| `--checkpoint-every` | Каждые сколько шагов сохранять модель в `checkpoints/tasochka`. |
| `--log-every` | Каждые сколько шагов печатать loss/скорость в терминал. |

## Как понять, что обучение идёт хорошо

В логе смотри на два числа:
- **`loss`** (на обучении) — должен **падать**. Скачет вверх-вниз рывками → уменьши `--lr`.
- **`val loss`** (на проверке) — тоже должен падать. Если начал **расти**, а `loss`
  всё падает — это **переобучение**. Останови и возьми чекпоинт с шага **до** роста.

Трейнер сам хранит лучший чекпоинт по `val loss` в `weights_best.safetensors`.
Также смотри `tok/s` (скорость) — если очень медленно, проверь что стоит `--bf16`.

Параметры генерации (можно добавлять к команде выше):

| Флаг | Простыми словами |
|---|---|
| `--temperature` | «Творческость». Ниже (0.5) = скучнее и увереннее, выше (1.0) = разнообразнее и рискованнее. |
| `--top-k` | Выбирать из K самых вероятных слов (напр. 50). |
| `--top-p` | Брать слова, пока их суммарная вероятность не наберёт p (напр. 0.92). |
| `--rep-penalty` | Штраф за повторы, чтобы не зацикливалась. 1.1–1.2. |
| `--max-new` | Сколько токенов сгенерировать максимум в ответе. |
| `--seed` | Зерно случайности для воспроизводимого ответа. |

## Чего реалистично ждать

Это **учебный проект** — понять, как языковые модели устроены изнутри, а не
сделать ChatGPT.

- **~180M (Mac)**: пишет осмысленные русские предложения, держит тему 2–3 реплики,
  знает, что она «Тасочка». Факты может выдумывать.
- **~1B (сервер, с большим корпусом)**: заметно связнее и грамотнее, лучше держит
  контекст. Но чтобы реально «заговорила», ей нужно ~15–20 млрд токенов и часы-дни
  обучения на GPU. С маленьким корпусом будет **недоучена по данным**.

Главный рычаг качества — **больше чистых данных и больше шагов обучения**.
