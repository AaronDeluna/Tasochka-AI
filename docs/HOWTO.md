# Как обучить модель — от проверки на Mac до сервера

Все команды запускаются **из корня проекта** с активированным окружением
(`source .venv/bin/activate`).

Порядок работы:

1. **Mac, smoke (~1 мин).** Проверяет, что весь конвейер работает.
2. **Mac, 1 час.** Показывает, что модель действительно учится: loss падает,
   появляется английский текст.
3. **Сервер.** Полноценный прогон с тем же кодом и данными в большем объёме
   ([SERVER.md](SERVER.md)).

---

## 0. Окружение (один раз)

```bash
./setup.sh && source .venv/bin/activate
```

`setup.sh` создаёт `.venv` и ставит MLX. Если `.venv` скопирован с другой машины
и не запускается, скрипт пересоздаёт его сам. Он выбирает самый свежий Python
из установленных. С системным 3.9 всё работает, но MLX там остаётся на версии
0.29. Чтобы получить свежий MLX, поставь `brew install python@3.12` и запусти
`setup.sh` заново.

## 1. Данные

```bash
python scripts/download_en.py --preset mac
```

Скрипт скачивает ~0.5 GB (≈120M токенов) в `datasets/en/`:

| Папка | Источник | Объём | Зачем |
|---|---|---|---|
| `fineweb_edu/` | HuggingFaceFW/fineweb-edu (sample-10BT) | 400M симв. | язык и знания: веб-страницы, отобранные по «образовательности» |
| `smoltalk/` | HuggingFaceTB/smol-smoltalk | 100M симв. | диалоги ассистента: правки текста, математика, код, вопросы-ответы |

Диалоги записываются в том же формате, в каком модель потом видит чат:

```
<user>
вопрос
</user>
<assistant>
ответ
</assistant>
```

Если связь оборвалась, повтори ту же команду: закачка продолжится с места
обрыва. Свои объёмы задаются так: `--web-chars 2e9 --chat-chars 2e8`.

**Как смешиваются источники.** Трейнер читает все `.txt` из папки `--data`
(рекурсивно) и перемежает файлы **пропорционально их размеру**. Доля диалогов
в обучении равна их доле на диске (здесь 20%), и в каждом участке корпуса,
включая валидационный хвост, смесь одинаковая. Чтобы усилить источник,
скачай его побольше. Скрытых повторов нет.

## 2. Smoke-тест (~1 минута)

```bash
python -m tasochka.train --config configs/mac-smoke.json
```

Ожидаемый результат: `init forward loss` около `~8.99`, за 300 шагов loss
падает примерно до 6, в `checkpoints/mac-smoke/` появляются веса. Если так,
конвейер исправен.

## 3. Проверка на час

```bash
python -m tasochka.train --config configs/mac-1h.json
```

Пресет обучает модель на ~16M параметров: 6 слоёв, dim 384, контекст 512,
5000 шагов, ~40M токенов. Первый запуск ~2.5 минуты учит токенизатор и
кодирует корпус, потом всё берётся из кэша.

На что смотреть:

| Шаг | Ориентир train loss (примерно) |
|---|---|
| 0 | ~9.7 (случайная модель, ≈ ln(16000)) |
| 300 | ~6 |
| 1000+ | 4.5 и ниже, снижается всё медленнее |
| 5000 | около 3.5–4 |

- `[val] ... loss` должен идти вниз вместе с train loss. Если val растёт, а
  train падает, модель переобучается. На этом объёме данных так быть не должно.
- `gnorm` должен держаться в пределах ~0.3–1.5. Постоянные всплески до 5+
  значат, что LR слишком большой.
- `ms/step` на MacBook Air растёт с ~470 до ~650 мс: ноутбук без вентилятора
  греется и сбрасывает частоты. Это нормально.

Обучение можно прервать (Ctrl+C) и продолжить той же командой: оно
возобновится с последнего чекпойнта (каждые 500 шагов) вместе с состоянием
оптимизатора. Любой параметр пресета можно перебить флагом:
`--config configs/mac-1h.json --max-steps 2000`.

## 4. Поговорить и оценить

```bash
python -m tasochka.generate --checkpoint checkpoints/mac-1h --chat
```

```bash
python -m tasochka.generate --checkpoint checkpoints/mac-1h --raw "The history of science"
```

```bash
python -m tasochka.eval --checkpoint checkpoints/mac-1h > eval_mac-1h.txt
```

`--raw` продолжает текст без чат-обёртки: так видно, усвоила ли модель сам язык.
`eval` прогоняет фиксированный набор из 23 английских промптов (факты, счёт,
инструкции, код). Если сохранять его вывод после каждого прогона, результаты
можно сравнивать между собой.

Веб-чат запускается так: `pip install -r requirements/server.txt`, затем
`python -m tasochka.server --checkpoint checkpoints/mac-1h`, затем открой
`web/index.html`.

**Чего ждать от часовой модели.** Грамматичные английские фразы, которые теряют
смысл через 1–2 предложения. Ответы в чате будут похожи по форме на ответ
ассистента, но без фактов. Это нормально для 16M параметров. Проверка нужна,
чтобы убедиться, что обучение работает, а не чтобы получить умную модель.

## 5. Дальше — сервер

Когда часовой прогон на Mac прошёл нормально, переходи к [SERVER.md](SERVER.md).
Там пресет `configs/server-125m.json` и ~13 GB данных.

## Параметры пресета простыми словами

| Ключ | Что это |
|---|---|
| `data` / `checkpoint` | откуда брать текст / куда сохранять модель, токенизатор и кэш токенов |
| `max_dataset_chars` | сколько символов корпуса использовать |
| `vocab_size` | размер BPE-словаря (8k для smoke, 16k для Mac, 32k для сервера) |
| `context_length` | сколько токенов модель видит за раз |
| `embedding_dim`, `num_layers`, `num_heads`, `num_kv_heads`, `feed_forward_dim` | размер модели. Число параметров печатается при старте |
| `batch_size` × `grad_accum` × `context_length` | токенов на один шаг оптимизатора |
| `lr`, `warmup_steps`, `min_lr_ratio` | скорость обучения: разгон, затем косинусный спуск до `lr × 0.1` |
| `bf16` | вычисления в bf16, веса оптимизатора в fp32. Быстрее без потери качества |
| `val_every`, `checkpoint_every` | как часто мерить val loss и сохраняться |

**Если поменял токенизатор или данные.** Кэш токенов
(`corpus_ids.bin`) пересобирается сам, когда меняются файлы данных. Токенизатор
(`tokenizer.json`) не пересобирается: при смене `vocab_size` или языка удали
папку чекпойнта или задай новый `checkpoint`.
