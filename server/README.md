# Обучение Tasochka 3B на NVIDIA-сервере

Все команды ниже выполняются **из корня репозитория**. Bash-скрипты сами переходят туда. Серверные данные, окружение, отчёты и веса находятся внутри `server/`. Mac-код не импортируется.

## Что реализовано

- Llama-совместимая архитектура с собственными случайными весами: 28 слоёв, hidden 3072, SwiGLU 8192, 24 query / 8 KV голов, RMSNorm, связанные embedding/output-веса. **2 966 203 392 параметра** при словаре 48 000.
- Собственный byte-level BPE: кириллица, Unicode и синтаксис кода без удаления символов и отступов. Только train-часть используется для обучения токенизатора. Чат имеет один формат в подготовке и генерации.
- BF16, Flash SDPA, gradient checkpointing, AdamW (β₂=0.95), warmup, cosine decay, clipping и accumulation. DeepSpeed ZeRO-3 распределяет состояние модели/оптимизатора по GPU.
- Cross entropy рассчитывается частями с повторным вычислением при backward: не создаётся полный тензор logits `[batch, 131072, 48000]`.
- Полные Trainer-checkpoints: веса, optimizer, scheduler, RNG и позиция обучения. Проверка конфигурации, словаря, метаданных данных и количества процессов при resume.
- Контекст: 4096 → 16384 → 32768 → 131072; YaRN относительно исходных 4096. Длинные этапы берут **непрерывные участки внутри отдельных книг**, без подмены длинного документа склейкой коротких.
- SFT: обучается ответ ассистента и маркер конца ответа; user/system/padding исключены из loss. Слишком длинные диалоги отбрасываются целиком, не обрезаются до одного вопроса. Экспорт читается обычным `AutoModelForCausalLM` без custom remote code.

## Оборудование и реалистичные ожидания

Базовый профиль запуска — **8 NVIDIA GPU с поддержкой BF16**, быстрой связью между ними и Linux. Для планирования можно рассматривать класс A100/H100 80GB, но **это не подтверждённый замер и не гарантия, что 128k поместится**. ZeRO-3 делит веса и состояние оптимизатора; последовательность и её активации между GPU не делятся. На 128k может понадобиться больше памяти на GPU либо отдельная реализация context/sequence parallelism, которой здесь пока нет.

Одни BF16-веса занимают примерно 5.52 GiB. Полное смешанное Adam-состояние до шардирования — ориентировочно 44.2 GiB, отдельно нужны активации, временные буферы и коммуникации. Планируйте сотни GB RAM и несколько TB SSD под текст, HF cache, uint32-токены, индексы и несколько checkpoint. Точный объём зависит от реально загруженных источников.

Начальные бюджеты: **60B** предъявленных токенов предобучения + **1B** на каждую ступень длинного контекста. Это не 60B гарантированно уникальных токенов: смесь сэмплируется с возвращением, повторение небольших источников отражается в их числе окон. Не выдавайте повторение маленького корпуса за достаточное предобучение. Для высокого качества может потребоваться существенно больше данных/вычислений и подбор гиперпараметров. Срок оценивайте после измерения `tokens/sec` на своём сервере: `оставшиеся токены / tokens_per_second`.

**Ограничение качества длинного контекста:** поставляемые длинные книги PG-19 англоязычные. Это основа для технического расширения окна, не подтверждение русского reasoning на 128k. Для целевого качества добавьте законно доступные длинные русские документы и длинные instruction-примеры; выполните оценку после SFT. Короткий SFT способен ухудшить использование длинного окна.

## Установка

Проверенный CPU-профиль тестов: Python 3.12, PyTorch 2.6.0, Transformers 4.51.3, Datasets 3.5.0, Accelerate 1.6.0. Серверный установщик ставит PyTorch 2.6.0 CUDA 12.4 и DeepSpeed 0.16.7; нужен совместимый NVIDIA-драйвер и среда сборки DeepSpeed. CUDA/ZeRO-3 здесь не проверены на реальных GPU.

```bash
bash server/setup.sh
source server/.venv/bin/activate
nvidia-smi
huggingface-cli login
```

Для `bigcode/starcoderdata` один раз примите условия доступа на странице датасета своим аккаунтом. Без этого загрузчик завершится ошибкой. Секрет HF_TOKEN не записывается в конфиги/метаданные.

## Данные

Манифест: `server/configs/datasets.json`. Загружаются данные, не чужие веса.

| Источник | Назначение | Доля предобучения |
|---|---|---:|
| [FineWeb2 rus_Cyrl](https://huggingface.co/datasets/HuggingFaceFW/fineweb-2) | Русский веб-корпус | 55% |
| [Wikipedia 20231101.ru](https://huggingface.co/datasets/wikimedia/wikipedia) | Русский справочный текст | 10% |
| FineWeb2 eng_Latn | Английский и техническая терминология | 5% |
| [StarCoderData](https://huggingface.co/datasets/bigcode/starcoderdata) | Python, Java, Go, JS, TS, C++, C, C#, Rust, SQL | 25%, поровну |
| [PG-19 Parquet](https://huggingface.co/datasets/emozilla/pg19) | Длинные книги; [оригинал](https://huggingface.co/datasets/deepmind/pg19) | 5% |
| [RuTurboAlpaca](https://huggingface.co/datasets/IlyaGusev/ru_turbo_alpaca) | Русские инструкции | 75% примеров SFT |
| [Magicoder OSS 75K](https://huggingface.co/datasets/ise-uiuc/Magicoder-OSS-Instruct-75K) | Инструкции по коду | 25% примеров SFT |

Условия источников и исходного кода различаются. Ссылки и сведения о лицензии сохраняются в манифесте; читайте карточки перед использованием/распространением. RuTurboAlpaca — небольшой синтетический корпус с известными ошибками, его недостаточно для сильного разговорного ассистента без дополнительной качественной разметки.

```bash
bash server/run.sh data
```

Загрузчик потоковый; точные дубликаты удаляются через SQLite на диске. Разбиение train/val определяется хешем целого документа, для SFT — вопроса. Альтернативные ответы на одинаковый вопрос не попадают в разные части. Это **exact dedup**, не полноценная фильтрация близких дубликатов и не проверка загрязнения внешних бенчмарков.

Revision каждого HF-источника разрешается в SHA и сохраняется в `raw/<source>/meta.json`; можно заранее задать `revision` в манифесте для воспроизводимой повторной загрузки. Завершённые источники пропускаются, незавершённый источник загружается заново. При изменении настроек используйте новый `--out`; не смешивайте старый токенизатор и новые веса.

`--max-records` у download — только проба доступа, не рабочий корпус. `preflight` отклоняет такие данные. Для отдельной пробы:

```bash
python -m server.download --sources alpaca_ru --max-records 100 --out server/data/download-probe
```

Свой источник можно добавить через манифест с `id`, `config`/`data_dir`, `field` для текста либо `prompt_fields`/`answer_field` для SFT. Загруженный JSONL диалога допускает несколько сообщений user/assistant/system. Для локальных данных подготовьте такой же `raw/<source>/{train,val}.jsonl` и `meta.json` по формату загрузчика. Никогда не включайте eval-набор в train. Перед сменой токенизатора нужно заново кодировать весь корпус и начинать новые веса.

## Проверка до долгого запуска

```bash
python -m pytest server/tests -q
python -m server.smoke --out server/smoke-output
python -m server.preflight
GPUS=8 bash server/run.sh pretrain --output server/runs/gpu-pilot --max-steps 10 --save-steps 5 --eval-steps 5
```

`smoke` не скачивает данные: проверяет токенизатор → бинарный корпус → pretrain → продолжение на 8k → SFT → экспорт → генерацию на маленькой CPU-модели. Отдельный тест проверяет **побитовое совпадение весов после прерывания и resume** с непрерывным обучением.

GPU-pilot проверяет память/скорость только для 4k. После каждого реального этапа сначала запустите следующий на 10 шагов в другом `--output`, особенно 128k. При OOM уменьшение accumulation не снижает память одной последовательности; нужен более подходящий GPU или изменение реализации. Математический SDPA fallback запрещён, чтобы не получить неожиданную квадратичную память.

## Полное обучение и восстановление

```bash
GPUS=8 bash server/run.sh all
```

Или поэтапно:

```bash
GPUS=8 bash server/run.sh pretrain
GPUS=8 bash server/run.sh 16k
GPUS=8 bash server/run.sh 32k
GPUS=8 bash server/run.sh 128k
GPUS=8 bash server/run.sh sft
```

`all` пропускает этапы с завершённым экспортом и продолжает незавершённые через checkpoint. При сбое до первого checkpoint выберите новый output или уберите только пустой незавершённый каталог после проверки его содержимого. У этапов сохраняются последние три checkpoint. Прерывание между ними теряет последние шаги; сохранения прямо при SIGKILL нет.

Ручное продолжение:

```bash
GPUS=8 bash server/run.sh pretrain --resume
```

Сохраняйте прежние GPU count, данные и CLI-параметры. `--resume` продолжает **тот же** optimizer/scheduler; `--init-from` начинает **новый этап** с весами завершённого предыдущего и новым оптимизатором. Токенизатор должен совпадать побайтно. Старые Mac-checkpoint несовместимы с новой архитектурой.

Логи содержат loss, grad_norm, learning_rate и размеры источников. `eval_results.json` — held-out loss; `final/stage_complete.json` подтверждает лишь завершение этапа, поле `quality_certified` остаётся false. `--tokens` считает номинальные токены фиксированных окон; для SFT используйте шаги/число примеров, поскольку длина и число обучаемых токенов переменные. SFT по умолчанию 1000 шагов: корректируйте по валидации, это не универсальный оптимум.

## Общение и приёмка качества

```bash
python -m server.chat --model server/runs/sft/final
python -m server.evaluate --model server/runs/sft/final --out server/reports/quality.jsonl
python -m server.evaluate --model server/runs/sft/final --out server/reports/context.jsonl \
  --needle-contexts 4096 16384 32768 131072 --haystack /absolute/path/to/held-out-russian-text.txt
```

`/reset` очищает диалог. Превышение контекста выдаёт явное сообщение, история не обрезается молча. KV cache включён при генерации. Для оценки 128k нужен достаточно длинный отдельный текст и GPU с подходящей памятью.

Русские ответы проверяйте на связность, грамматику, выполнение инструкции и сохранение смысла в многоходовом диалоге. Код — на корректность и компиляцию/тесты отдельно для каждого языка; поставляемые промпты сохраняют ответы для проверки и **не исполняют сгенерированный код**. Needle-тест проверяет извлечение случайного номера на 10/50/90% глубины при точном токенном бюджете. Это один диагностический тест, не доказательство общего понимания 128k. До и после SFT сравните короткие русские задачи, код и длинные тесты.
